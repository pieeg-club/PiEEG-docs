# BrainFlow Devices

PiEEG Cloud includes a **BrainFlow Devices** tab in the Session Lobby at [cloud.pieeg.com/lobby](https://cloud.pieeg.com/lobby) that connects third-party EEG and biosignal boards directly in the browser over **Web Bluetooth (GATT)** and **Web Serial (USB CDC / FTDI / CP210x / Bluetooth SPP)** without installing Python or native drivers.

<Callout type="info">
  **Access & Licensing Policy:** PiEEG Cloud is included at no cost with all PiEEG hardware. Browser-native support for third-party BrainFlow-compatible boards is unlocked free during the launch period (no sign-in required) and will transition to a small one-time unlock or subscription later.
</Callout>

## Architecture & Signal Path

```
Physical Board (WebBLE GATT or WebSerial UART)
  ↓
BrainFlow Profile Driver (src/lib/brainflow/)
  - GATT characteristic subscription or UART baud/command init
  - Frame alignment (0xA0..0xC0, Fletcher trailer, or bitfield tags)
  - ADC code → microvolt (µV) conversion
  ↓
Browser-Side DspChain (src/lib/dsp.ts)
  - Hampel outlier spike filter
  - 5th-order Butterworth bandpass (1 Hz to min(40 Hz, 0.45 * fs))
  - IIR line-noise notch filter (50 / 60 Hz when < Nyquist)
  ↓
Ring Buffer → Waveforms, 256-pt FFT, 3D Topomap / 3D IMU Hand, Live Lab, 35+ Experiences
```

When you select a board from the **BrainFlow Devices** tab:

1. **User-gesture hardware pairing**: Clicking **Connect** invokes `navigator.bluetooth.requestDevice()` (filtered by the board's GATT service UUIDs and advertised name prefixes) or `navigator.serial.requestPort()`.
2. **Protocol initialization**: The driver transmits the board's start sequence (for example, `v` / `d` / `b` on Cyton, preset `p21` + `d` on Muse, `0x3F` / `0xA3 0x00` / `0x01` / `0x07` on Shimmer3, or `0x01 0x62` on AAVAA V3) and sends the matching stop sequence on disconnect.
3. **Sample rate & Nyquist adaptation**: The session's live sample rate store (`sampleRateStore`) updates to the board's native ADC rate (`50 Hz` to `512 Hz`). The browser-side `DspChain` automatically clamps its upper bandpass cutoff to `min(40 Hz, floor(0.45 * sampleRate))` and disables the 50/60 Hz notch if the line frequency exceeds Nyquist.
4. **IMU & 3D Hand Telemetry**: Boards that transmit 6-axis accelerometer and gyroscope data on the wire (`Shimmer3`, `Knight IMU`, `BrainAlive`, `Muse 2`, `Muse S`, `Muse S Athena`, `Muse 2016`) feed live IMU samples into the browser complementary filter (`auraVrImuStore`). In the dashboard FFT pane, you can switch between the **3D Topomap** and the **3D Hand · IMU** view (`AuraHandView`, showing 3D orientation, Roll/Pitch/Yaw, Accel/Gyro telemetry, and per-channel ExG RMS bars). `Shimmer3` and `Knight IMU` default to the **3D Hand · IMU** view; scalp + IMU headsets default to the **Topomap** view.

## Supported Browser-Native Boards (19 Profiles)

Only boards from BrainFlow whose physical layer operates over open BLE GATT characteristics or serial COM ports are listed in the browser-native tab. First-party boards (`PIEEG_BOARD` `56` and `IRONBCI_32_BOARD` `65`) are listed in the dedicated **PiEEG Devices** tab. Boards that require closed vendor C++ shared libraries (`.dll` / `.so` / `.dylib`) or raw OS UDP/TCP server sockets cannot run inside the browser security sandbox.

## Automated Upstream Compatibility Check

PiEEG Cloud tracks all 66 `BoardIds` defined in upstream [`brainflow-dev/brainflow`](https://github.com/brainflow-dev/brainflow):

- **19 Browser-native boards** (`src/lib/brainflow/catalog.ts`): 7 WebBLE + 12 WebSerial profiles.
- **2 First-party boards** (`PIEEG_BOARD` `56`, `IRONBCI_32_BOARD` `65`): handled directly in the first-party **PiEEG Devices** tab.
- **3 Virtual boards** (`PLAYBACK_FILE_BOARD` `-3`, `STREAMING_BOARD` `-2`, `SYNTHETIC_BOARD` `-1`).
- **5 Deprecated BLED112 dongle wrappers** (`GANGLION_BOARD` `1`, `BRAINBIT_BLED_BOARD` `18`, `MUSE_S_BLED_BOARD` `21`, `MUSE_2_BLED_BOARD` `22`, `MUSE_2016_BLED_BOARD` `42`): superseded by native WebBLE profiles.
- **10 Raw TCP/UDP socket boards** (`GALEA_BOARD` `3`, `GANGLION_WIFI_BOARD` `4`, `CYTON_WIFI_BOARD` `5`, `CYTON_DAISY_WIFI_BOARD` `6`, `NOTION_1_BOARD` `13`, `NOTION_2_BOARD` `14`, `CROWN_BOARD` `23`, `EMOTIBIT_BOARD` `47`, `NTL_WIFI_BOARD` `50`, `BIOLISTENER_BOARD` `64`).
- **27 Closed-source vendor SDK boards** (`BRAINBIT_BOARD` `7`, `UNICORN_BOARD` `8`, `CALLIBRI_*` `9-11`, `GFORCE_*` `16, 19`, `ANT_NEURO_EE_*` `24-36, 51`, `SYNCHRONI_*` / `OB5000` / `OB3000` `58-63`).

A weekly GitHub Action (`.github/workflows/brainflow-upstream-check.yml`) runs `npm run check:brainflow` (`cloud/scripts/check-brainflow-upstream.mjs`) every Monday at `09:00 UTC`. The script fetches `brainflow_constants.h`, `brainflow_boards.cpp`, and `board_controller.cpp` from upstream `master` and opens a GitHub Issue only if a new `BoardIds` enum entry or ID change is detected.

## How to Connect

<Steps>
### Open the Session Lobby

Open [cloud.pieeg.com/lobby](https://cloud.pieeg.com/lobby) in a desktop Chromium browser (Chrome, Edge, Brave, or Opera) over HTTPS.

### Switch to the BrainFlow Devices tab

In the **Connect Your Device** panel, select the **BrainFlow Devices** tab. You can filter by **Web Bluetooth** or **Web Serial**, or search by board name, `BoardId` number, or 10-20 channel label.

### Pair or select the serial port

Click **Connect** on your board's card:
- **Web Bluetooth boards**: Select your powered-on headset/board from the browser's Bluetooth chooser.
- **Web Serial boards**: Select the USB dongle, USB CDC device, or OS-paired Bluetooth SPP virtual COM port from the serial port chooser.
</Steps>
